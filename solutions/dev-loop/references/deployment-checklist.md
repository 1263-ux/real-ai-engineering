# deployment-checklist — 部署/集成验收清单（按需取用）

> 适用：远程部署、发布、实机集成、多服务联动、插件安装等 L3/高风险任务。
> 按需取用，不是默认流程；小任务不套本清单。

## 两个 Gate（拆分，不混为一谈）

- **Gate A（源码）**：构建通过、类型契约、定向测试 + 完整测试、diff 白名单（仅任务文件）。
- **Gate B（实机/安装包）**：tarball/安装包、安装目录、真实 runtime 加载（Node 版本）、服务重启、健康检查。

Gate A 通过 ≠ Gate B 通过；"页面能打开" ≠ "部署成功"。

## 验收矩阵（开始前固定，按任务裁剪）

| 层 | 检查项 |
|---|---|
| 匿名 | 匿名页面、匿名 API（预期拒绝或受限） |
| 登录 | 登录页面、登录后页面、manifest |
| API | 业务 API、WebSocket、权限接口（settings/credentials 等） |
| 模型 | 模型配置可见性、模型实际调用（非仅 UI） |
| 业务插件 | 插件设置读写、插件召回/核心闭环 |
| 多账号 | 第二账号、权限隔离（若适用） |

## 原子发布流程（失败自动回滚）

```text
备份 → 构建 → 静态校验 → 单元测试 → 重启 → 健康检查 → 外部验收 → 失败回滚
```

- 备份：改动前保留可回退副本（远端 + 本地）。
- 每一步有明确通过判据；任一步失败走回滚，不带着失败继续。

## 插件兼容性预检（安装前）

- Node / Python 版本
- 插件入口是 JS 还是 TS（TS 源不能直接运行，需构建产物）
- ESM / CJS 兼容性
- 宿主插件 API 版本
- 是否需要构建产物、构建后入口指向

## 证据关联（防误判）

- 浏览器/工具超时 ≠ 业务失败；超时后查最终状态：页面内容、会话记录、服务日志、实际返回。
- 验收结论写清：哪些是完整实测通过，哪些由构建/回归/HTTP 检查间接支撑；禁止把超时说成成功。
