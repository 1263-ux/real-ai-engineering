# dev-loop v3.2 变更设计

> 状态：**APPROVED（G1 2026-08-18，按默认落地）→ 已实施为 v3.2 并冻结**
> 基线：v3.1 → v3.2（见 `FROZEN.md`）
> 来源：2026-08 真实会话复盘（npx/Node 收口任务暴露：零装载、零工件、环境失败误路由）

## Goal

让 dev-loop 在**真实任务**里能被触发、能覆盖「运维 / 发布 / 网络排障」形态，并修复本轮暴露的三类问题：没触发（零装载）、零工件（跨 checkpoint 丢状态）、环境失败误路由（被当逻辑失败计入 RETHINK）。

## Constraints

- 不新增状态机状态（沿用 `DESIGN→PLAN→IMPLEMENT→VERIFY→TRIAL→DONE` + `BLOCKED/RETHINK`）。
- 不新增主工件类型（沿用 4 primary + CURRENT_STATE + STATUS）。
- 不新增 Expert 流程（沿用「新增 Expert = 填一行表格」）。
- 不改 4 门禁语义（G1–G4）。
- 与 v3.1 相同的语言风格与结构（表格、短句、中英混排）。
- 两处同步：全局安装 `~/.agents/skills/dev-loop` 与 repo `solutions/dev-loop`，改后 SHA 校验一致。

## Non-goals

- **不改宿主（DSH）行为**：自动装载提示 / 自动播种模板 / catalog 变更——本轮不涉及宿主侧改动，只把「必须装载 + 可核查信号」写进技能文本。
- **不重写宪法十条**：C5 只动「核心思想」第 2 条 + Playbook + Expert 规范，宪法英文十条一行不改。
- 不做「运维状态机」完整重设计（那是 v4 候选，本轮只加轻路径一行）。
- 不清理 `cases/` 与 `FROZEN.md` 之外的存量内容。

## Key Decisions

- **D1** 触发规则进 SKILL.md 正文（新增「触发条件」段），不依赖宿主自动装载；可核查信号 = 多步任务开始时是否已播种 `.agent/CURRENT_STATE`。
- **D2** 运维 / 发布走轻路径：Playbook 加一行，免 DESIGN、免形式化 AC，PLAN 允许清单级。
- **D3** 环境 / 外部失败显式归类 BLOCKED，独立计数，不进「同类逻辑失败 2 次 → RETHINK」。
- **D4** 工件门槛降到「一句话级」：CURRENT_STATE / RESULT 最小一行，跨 checkpoint / 跨 Expert 不丢状态。
- **D5** 高风险 review 的独立 Expert 从「应做」升为「必做至少一次」，实现者自审不计数。

## Changes（位置 → 现状 → 改为）

### C1 新增「触发条件」段

- **位置**：`## 核心思想` 之后、`## Constitution` 之前。
- **现状**：全文无触发段；只有「简单任务只在心里走状态」。
- **改为**（新增段落）：

```markdown
## 触发条件（什么时候必须装载本 Skill）

目标包含以下任一项 → 第一步必须装载本 Skill（`skill dev-loop`）并播种
`.agent/CURRENT_STATE`（一句话即可：当前状态 + 下一步）：

- 多文件改动 / 跨文件重构
- 多步骤 git 操作 / 分支 / PR / 发布 / review / 同步
- 工具链 / 运行时 / 环境迁移（node / npm / 代理 / 服务切换等）
- 任何完成后需要他人验收、或跨会话继续的结果

不满足上述条件的单步任务（查询 / 单文件小改 / 一次性命令）可不装载，
但完成后在会话里留一行结论（最小 RESULT：结论 + 残留）。
```

- **影响**：「没装载」从不可见变为可核查（审查者看 CURRENT_STATE 是否存在）。

### C2 Playbook 加「运维 / 发布」行

- **位置**：`## Playbook` 表格。
- **现状**：4 行（简单 / 复杂 / 高风险 / 架构级），全为写码假设。
- **改为**：表格加一行，表下加说明：

```markdown
| 运维/发布（git/PR/review/同步/网络排障/环境迁移） | PLAN(清单) → G2(大范围时) → 执行 → RESULT | 按需 |
```

```markdown
- 运维/发布类任务**不产 DESIGN、不形式化 AC**；PLAN 可以是清单级（改什么 / 顺序 / 回滚）；
  验证 = 真实运行结果 / diff / git 状态，不是 test/build。
```

- **影响**：本轮约 80% 的活（git 分支、PR 审批、代理切换、kroki 重试）有明确归属路径。

### C3 Failure Routing 加「环境 / 外部失败」类

- **位置**：`## Failure Routing` 表格 + 规则行。
- **现状**：4 类逻辑失败 + RETHINK；无环境失败归类，会被误计入「2 次 → RETHINK」。
- **改为**：表格加一行 + 规则加两条：

```markdown
| 环境/外部失败（网络/代理/第三方 500/认证/配额/服务抽风） | 独立计数，不进逻辑失败计数 | BLOCKED |
```

```markdown
- 环境/外部失败**不触发 RETHINK**；RETHINK 只针对 Implementation/Plan/Design/Requirement 逻辑失败。
- 环境失败走固定排障序：查代理/端口/环境变量 → 换源/镜像 → 退避重试（设上限）→ 仍未解决则 BLOCKED 上报人工。
```

- **影响**：kroki 500、代理 10808↔7890 切换等不再产生假 RETHINK 信号。

### C4 工件门槛降到「一句话级」

- **位置**：`## 状态机` 下「- 简单任务只在心里走状态，不产工件；复杂/高风险任务才落 `.agent/` 工件。」
- **现状**：简单任务零工件 → 跨 checkpoint 只能靠聊天（本轮被压缩即是证据）。
- **改为**：

```markdown
- 工件门槛：**所有任务最低一句话级工件**。多步任务开始时播种 `.agent/CURRENT_STATE`
  （最小一行：状态 + 下一步），每轮循环后更新；完成时留最小 `RESULT`（结论 + 残留）。
  简单任务可在心里走状态，但至少留最小结论行；复杂/高风险任务仍落完整工件（DESIGN / PLAN / RESULT）。
```

- **影响**：会话被 checkpoint 压缩时状态不丢；跨 Expert 交接有最小锚点。

### C5 高风险 review 必选独立 Expert

- **位置**：`## 核心思想` 第 2 条 + `## Playbook` 高风险行 + `## Expert 规范` 末条。
- **现状**：
  - 核心思想 2：「高风险才升级独立 Expert」（「才」是许可语气）
  - Playbook：「高风险（认证/DB/协议/重构/发布）｜复杂路径 + 独立 Expert 审查」（可被跳过）
  - Expert 规范：「**默认一次任务最多一次稀缺 Expert 升级**」（只有上限，无下限）
- **改为**：
  - 核心思想 2：「高风险**必须**升级独立 Expert（至少一次，自审不计数）」
  - Playbook 高风险行：`复杂路径 + **必须至少一次**独立 Expert 审查`，表下加：`实现者自审不得充当独立审查；审查须为独立上下文（EXPERT_PACKET → fresh context）`
  - Expert 规范末条追加：`高风险任务下限 = 至少一次独立 Expert；与上限（最多一次）共同构成稀缺额度的使用边界`
- **影响**：#31 类（实现者自审把 review 字段语义读错）的翻车路径被文本封死。
