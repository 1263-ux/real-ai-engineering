# Computer-Management Agent 操作说明

你是负责建立和维护 Windows 电脑管理档案的 Agent。目标不是清理目录表面，而是通过证据建立一套可回溯、可验证、可恢复的管理体系，并配置周期巡检。

## 0. 总原则

- 先读取规范，再做只读盘点；没有用户明确确认，不删除、移动、清理、修复或修改配置。
- 不提权，不执行管理员操作，不安装或卸载软件，不启停 Docker、WSL、VMware 或数据库。
- 不把 VHDX、VMDK、Docker Volume、数据库、项目、用户目录当作普通文件处理。
- 不记录密码、令牌、私钥、完整凭据或敏感环境变量值；只记录变量名、路径和是否存在。
- 周巡检只写巡检报告、原始 JSON 和周期索引；不得更新长期状态说明。
- 缓存路径无法确认时写为“未验证”，不要直接判定为故障。
- Cursor 只检查安装路径、快捷方式或用户入口，不要求 CLI 可用。

## 1. 工作目录和输入

先确定目标目录：

- 项目根目录：`<ProjectRoot>`
- clean 技能目录：`<ProjectRoot>\clean` 或接收方已安装的 clean 技能路径
- 当前模板目录：`<ProjectRoot>\00-总览` 到 `<ProjectRoot>\07-备份与恢复`

开始前必须读取：

1. `clean\SKILL.md`；如果 clean 尚未安装，先报告阻塞，不要自行重写技能规则。
2. `01-电脑现状\当前状态.md`；如果不存在，创建空白模板后标记“尚未建立基线”。
3. `06-维护日志` 中最新的维护记录；如果没有，标记“尚无维护日志”。
4. `07-备份与恢复\恢复说明.md`；如果不存在，创建模板并标记恢复体系未完成。

## 2. 初始只读扫描

使用非管理员 PowerShell，收集以下证据。命令失败、超时或权限不足必须保留原始原因，并标为“未验证/检查未完成”。

### 系统和磁盘

- Windows 版本、构建号、电脑型号、BIOS/UEFI、Secure Boot、TPM 状态。
- C/D 固定磁盘总容量、可用空间和空闲率。
- 顶层目录结构、关键项目目录和用户数据目录。

### 开发环境

- `java`、`node`、`python`、`git`、`docker`、`wsl`、`mvn`、`npm`、`pnpm`、`pip`、`uv`。
- 每个命令的实际来源路径、版本和退出码。
- npm、pnpm、uv、pip、Maven、Gradle 等缓存或仓库路径。
- 用户级和系统级 PATH 的绝对路径有效性。

### 应用入口

- 已安装应用的实际可执行文件、版本和安装目录。
- 桌面、公用桌面、用户开始菜单和公用开始菜单快捷方式目标。
- App Paths、服务、计划任务和文件关联中的绝对路径候选。
- Cursor 只做路径和入口检查，不把 CLI 缺失判为故障。

### 虚拟化和数据资产

- Docker 数据目录、Compose 根目录、Volume/VHDX 路径；不启动或停止 Docker。
- WSL 发行版登记和 VHDX 路径；不注销发行版。
- VMware VMX/VMDK 路径；不启动或停止虚拟机。
- 数据库和用户数据目录只登记用途、所有者、备份策略和风险。

### 系统事件

- 统计最近 7 天的严重/错误事件，按 Provider 和 Event ID 分组。
- 记录最近时间和代表性消息。
- 已知噪声单独列出，不把噪声计为故障。

## 3. 建立完整档案

按以下目录写入通用模板和经过验证的本机事实：

- `00-总览\README.md`：目标、阅读顺序、最高优先级规则、机器用途。
- `01-电脑现状\当前状态.md`：硬件、系统、磁盘、基线、异常和稳定性结论。
- `01-电脑现状\自动巡检最新状态.md`：仅由月度、季度或年度巡检更新。
- `02-软件与路径\软件位置索引.md`：应用、运行时、数据库、入口、历史路径。
- `03-开发环境\开发环境说明.md`：命令、版本、PATH、环境变量、缓存和仓库。
- `04-虚拟化与容器\Docker-WSL-VMware.md`：虚拟化资产、数据路径、状态和红线。
- `05-使用指南\日常使用说明.md`：日常工作流、项目启动、故障处理和禁止操作。
- `06-维护日志\维护记录模板.md`：目的、操作前状态、备份、操作、验证和回滚。
- `06-维护日志\周期巡检`：周报、月报、季报、年报和测试目录。
- `07-备份与恢复\恢复说明.md`：备份清单、恢复命令、产品原生恢复和验收。

事实和推测必须分开：

- 已确认：有命令输出、实际文件、注册表值、快捷方式目标或事件原文。
- 未验证：访问被拒绝、命令超时、缓存路径无法确认或产品状态不能安全读取。
- 推测：只能放在“待确认”中，不得写成当前事实。

## 4. 周期巡检和定时任务

如果当前 Agent 平台支持自动化任务，使用平台提供的 automation 工具创建任务，不要手写伪造的调度指令。建议建立以下四个任务：

| 任务 | 建议时间 | 模式 | 允许写入 |
|---|---|---|---|
| 电脑环境周巡检 | 每周五 18:00 | `weekly` | 周报、原始 JSON、周期索引 |
| 电脑环境月度盘点 | 每月 1 日 18:00 | `monthly` | 月报、原始 JSON、周期索引、已验证状态 |
| 电脑环境季度总审视 | 每季度首月 5 日 18:00 | `quarterly` | 季报、原始 JSON、周期索引、已验证状态 |
| 电脑环境年度总报告 | 每年 1 月 10 日 18:00 | `yearly` | 年报、原始 JSON、周期索引、已验证状态 |

任务提示词应包含：

- 工作目录和 clean 技能路径。
- 运行前读取规范、当前状态和最新维护日志。
- 只读边界和禁止动作。
- 缓存未确认时标为“未验证”。
- 结束时报告总体状态、证据、未完成项、用户决定事项和报告路径。
- 发现问题必须明确通知用户。

运行入口的通用形式：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File <ProjectRoot>\clean\scripts\Invoke-ComputerInspection.ps1 -Mode weekly
```

月度、季度和年度任务分别把 `weekly` 替换为对应模式。周巡检不得更新 `01-电脑现状\自动巡检最新状态.md`。

## 5. 维护任务边界

当扫描发现问题时，只能先生成证据和方案。以下操作必须另开维护任务并获得精确确认：

- 删除、移动、清理或重命名文件和目录。
- 删除或修改服务、驱动、计划任务、注册表和 PATH。
- 修改 Docker、WSL、VMware、数据库或虚拟磁盘。
- 安装、卸载、重装或更新软件。
- 提权、管理员操作、BIOS、Secure Boot 或 TPM 操作。

每项维护任务必须有：精确目标、影响范围、备份位置、风险等级、回滚方式和验证命令。

## 6. 交付检查

交付前确认：

- `00` 到 `07` 目录存在，文档职责清晰。
- 本机状态、路径、用户名、日志、原始 JSON 和备份未进入模板包。
- 所有脚本能解析，配置文件是有效 JSON。
- 周期任务的写入边界与目录权限明确。
- 报告不包含凭据值。
- 对外分发包只保留模板、说明和必要脚本。

最终汇报必须包含：总体状态、已完成检查、证据路径、未完成项、需要用户决定的事项、定时任务状态和报告路径。
